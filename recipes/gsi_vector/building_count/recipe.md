# gsi_vector / building_count

## 何をする

地理院地図Vector（`experimental_bvmap`）の `building` レイヤを XYZ タイルで取り、
**タイル境界で割れた面を結合してから**棟数を数える。
重心を取れば点群になり、流域の上流累積などに使える。

★**このレシピの要は「取ること」ではなく「数える前に結合すること」。**
結合を忘れると、棟数も、それを土台にした順位も、静かにふくらむ。

## API情報

- `https://cyberjapandata.gsi.go.jp/xyz/experimental_bvmap/{z}/{x}/{y}.pbf`
- **z16 までしか無い**（2026-10-26 に1地点で z17=404・z16=200 を確認）。ベクトルなので z16 の形をそのまま使う。z16 で描かれていない小さな建物は数えられない
- 認証不要・出典明示のみ。User-Agent は付けて取る（付けない場合は確かめていない）
- デコードは `mapbox_vector_tile`。レイヤ名は `building` `road` `river` `waterarea`
  `landforml` `contour` `label` `symbol` `boundary` `structurel` `elevation`

## 使い方

1. bbox から z16 のタイル範囲を出し、`.pbf` を取得（キャッシュする）。bbox の端で切れた建物は数え方を決めて書く（重心が bbox 内のものだけ数える等）
2. 各タイルの `building` を取り出し、**タイル内座標（extent=4096）→経緯度**に直す
3. **全タイルぶんを `shapely.ops.unary_union` で結合**する
4. 結合後の面を数える／重心を取る

## ★ハマり所（全て実際に踏んだ）

1. **★★★1棟がタイル境界で割れる。結合しないと多く数える。**
   千葉県北部の約8×9km（z16タイル340枚）の1例で
   **生ポリゴン 61,709面 → 結合後 54,329面**（記録 `references/20261026_recount.json`）。
   小さい図郭で見ると **5,818面 → 1,092面（81.2%減）** で、割れは1枚のタイルの中でも起きている
   （マルチパートの分割）。重心をそのまま数えた旧データは **61,635棟** で、**+13.4%** だった。ほかの地域で何%になるかは測っていない。

2. **★★割れているかは、タイル境界からの距離で測れる。**
   各点のタイル内座標の小数部が0または1に近いものを数える。
   z16 のタイル幅は赤道で約611m、北緯35.7°で約496m（緯度で変わるので、その緯度の幅で換算する）。
   上の1例を 2026-10-26 に測り直すと、境界から3m以内は**結合前の点で5.47%、結合後で2.58%**だった。
   （旧版の「4.59%」は再現しなかった。611m で換算すると4.51%。）結合前後で比べて、境界への貼り付きが減るかを見る。

3. **★★★「数えたもの」を作るスクリプトを残す。**
   対話の中で作った点群ファイルだけが残り、**作り直せない状態で全部の順位の土台になっていた**。
   指摘されるまで気づかなかった。取得→結合→計数を1本のスクリプトにする。

4. **★差し替える前に、旧データを再現できることを確かめる。**
   新しい数え方に替えるとき、**旧データで旧の結果が再現できる**ことを先に確認する。
   上流累積を作り直して保存済みの配列と**完全一致**することを見てから差し替えた。
   ここを飛ばすと、差が「直った」のか「別のバグ」なのか分からなくなる。

5. **★z17 は無い。** z16 が上限（z17 は404）。拡大したいときは z16 の形を大きく描く。

6. **★基本測量成果ではないと国土地理院が明記している。**
   （github.com/gsi-cyberjapan/gsimaps-vector-experiment の README:「本提供実験のベクトルタイルは基本測量成果と位置付けているものではありません」。2026-10-26 確認）
   棟数を**公式の値として使わない**。傾向・相対比較に使い、図と本文にこの但し書きを入れる。

7. **ftCode は仕様書で引く。** 国土地理院「地理院地図Vector 提供実験 データ仕様」（https://maps.gsi.go.jp/help/pdf/vector/dataspec.pdf）の
   building は `3102` 堅ろう建物・`3103` 高層建物（2026-10-26 確認）。仕様に無いコード値が出たら、名前を付けずにコード値のまま集計して出す。

## 効くケース

- 市区町村〜数km四方の**相対的な棟数**（どの谷の上流に多いか、どの区域に何棟あるか）
- 流域の上流累積の重み（建物数を流向に沿って積み上げる）
- 建物の**位置**が要る用途（重心点で足りる）

## 効かないケース

- **公式の建物棟数**（基本測量成果ではない。住宅・土地統計や固定資産とは別物）
- 1棟ごとの属性（用途・階数・建築年は入っていない）
- 小屋・車庫と住宅の区別（面の大小でしか切れない）

## 出典表記

「国土地理院 地理院地図Vector（experimental_bvmap。**試験公開であり基本測量成果ではありません**）
により作成。」棟数を出す図には、**結合したこと**と**結合前後の面数**も書く。

## このレシピを使うLLMへのヒント

- **棟数を使う前に、結合前後の面数を必ず印字する。** 減った分だけ、結合しない数字はふくらんでいる。
  結合しない数字を使わない（何%なら使ってよいという線は無い）。
- 棟数が「順位」の土台になるなら、**結合の有無で順位が入れ替わるかを確かめる。**
  上の1例（上流累積の棟数で並べた順位）では上位5件は同じで、下位で入れ替わりが出た（記録 `shisui_moritsuchi_p000/scripts/make_excel.py` の検証ログ。測り直していない）。
- タイルはキャッシュする。結合のやり直しに何度も取りに行かない。
