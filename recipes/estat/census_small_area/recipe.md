# e-Stat / census_small_area（国勢調査 小地域集計 町丁・字等別）

## 何をする
国勢調査の小地域集計（町丁・字等別）を1市区町村ぶん取り、**末端の地域だけ**を CSV にする。
境界（Shapefile）も同じ地域コードで取れるので、町丁単位の階級区分図がそのまま描ける。
末端の合計が市区町村の計と一致するかを、列ごとに検算して metadata に残す。

```bash
python fetch.py --find 産業 --pref 愛知県          # ファイル番号を探す（要 ESTAT_APP_ID）
python fetch.py --stat-inf-id 000032210330 --list-cols
python fetch.py --stat-inf-id 000032210330 --city 23214 --cols 0_総数,R1_,R2_,R3_,T_ --boundary
```

出力は `YYYYMMDD_estat_small_area_<番号>_<市区町村>.csv`（1行＝1地域）と metadata.json、`--boundary` で境界の zip。

## なぜこのレシピがあるか
2026-10-25、講師の Windows 機で AI（Antigravity）が **レシピなしで**蒲郡市の産業3部門別の町丁図を作った（修正込みで約20分）。
こちらで同じスクリプトを走らせると、CSV は改行コードを除いて一致し、市の計（就業者 40,789人・第1次 1,655・第2次 15,462・第3次 22,877）は
社会・人口統計体系の市区町村データと4値とも一致した。

ただし、その作りは**蒲郡市では正しいが、ほかの市では計が合わない**。新潟市中央区の年齢の表に当てると 1,200人足りなかった。
秘匿の人数が「親」の行に入る場合（下の5）を、蒲郡市が1件も持っていなかったためである。
1つの市で検算が通っても、**規則が正しいとは限らない**。このレシピは愛知県69・新潟県37の全市区町村で検算を通してある。

## ハマり所

1. **統計表の検索に出てこない。番号はデータカタログで探す**
2. **1つの地域に「総数・男・女」の3行がある**
3. **地域階層レベル3は、レベル4の合計**。末端はレベル2＋レベル4
4. **「X」は秘匿、「-」は0**。秘匿の人数は隣の地域に合算されている
5. **秘匿の合算先が「親」（レベル3）のことがある**
6. **列は見出しで選ぶ。見出しの形も表ごとに違う**
7. **境界は KEY_CODE で結ぶ。飛び地で同じコードが2行、水面が1行ある**
8. **Windows の pandas は CSV を CRLF で書く**。csv_sha256 が機械ごとに変わる

### 1. 統計表の検索に出てこない
`getStatsList` を `statsCode=00200521`（国勢調査）で引いても、小地域集計は出てこない（`docs/api_notes/estat.md`）。
小地域集計は**都道府県×表ごとのファイル**で、`stat-search/file-download?statInfId=…&fileKind=1` から直接落とす（cp932 の CSV）。
番号は **`getDataCatalog`** を `searchWord="小地域 AND 産業 AND 愛知県"` で引くと出る（`--find`）。
愛知県の第11表（産業大分類）は `000032210330`、新潟県の第3表（年齢5歳階級）は `000032163305`。

### 2. 総数・男・女の3行
男女の列（2列目）が「総数」「男」「女」の3行が、同じ地域コードで並ぶ。**「総数」だけを取る。** 全部足すと2倍になる。

### 3. レベル3はレベル4の合計
「地域階層レベル」は 1＝市区町村、2＝丁目の無い町（大字）、3＝丁目のある町の計、4＝字・丁目。
レベル3の行（例「相楽町」、名前が「町丁字コード6800の計」のこともある）は、その下のレベル4の合計である。
**末端はレベル2＋レベル4。** 蒲郡市は 18＋361＝379地域で、境界の KEY_CODE の種類（379）と1対1に合う。

### 4. 「X」と「-」
「X」は秘匿（人数が少なく伏せた）、「-」は0。区別して持つ（このレシピは X を空欄、- を0にする）。
秘匿の行の「秘匿先情報」列に合算先の町丁字コードがあり、人数はそちらの行に**すでに足されている**。推測で割り戻さない。
合算先の行には「合算地域あり」と、合算された地域のコードが入る。合算先は別の大字のこともある（新潟市中央区 西中町→下旭町）。

### 5. 合算先が親のことがある
ある町の丁目がすべて秘匿だと、合算先は**その町のレベル3の行**になる。新潟市中央区の美咲町は一丁目・二丁目がともに X で、
1,200人は「美咲町」（レベル3）の行にだけある。3のとおりレベル3を捨てると、この人数が消える。
このレシピは、秘匿の合算先になったレベル3を `status=merged_parent` として末端と並べて残し、
覆う地域を `merged_parent_covers` に書く。地図では、その地域の境界を合わせて1つに塗る。
愛知県で28件、新潟県で10件あった。**珍しくない。** 1つの市だけで確かめると見落とす（蒲郡市には無かった）。

### 6. 列は見出しで選ぶ
4行目が見出しで、第11表は `0_総数` `R1_（再掲）第1次産業` のようにコード付き、第3表は `総数` `0～4歳` とコードが無い。
**位置で選ぶと、表が変わったときに黙って別の列を読む。** `--list-cols` で見出しを出し、`--cols` に頭の文字を渡す（1本に当たらなければ止まる）。

### 7. 境界
境界は統計GISの「町丁・字等別境界」（令和2年 `dlserveyId=A002005212020`、平成27年 `A002005212015`）。Shapefile の文字は cp932。
`KEY_CODE`＝市区町村コード5桁＋町丁字コード（4桁か6桁）で、CSV と同じ。
**同じ KEY_CODE が2行ある**（飛び地。`AREA_MAX_F=M` が大きいほう）ので `dissolve(by="KEY_CODE")` してから結ぶ。
`HCODE` は 8101＝町丁・字等、**8154＝水面**（蒲郡市では「三河港の水域」）。陸の図からは外す。

### 8. CRLF
pandas の `to_csv` は、改行を指定しないと**その機械の改行**（Windows は CRLF）で書く。同じデータでも csv_sha256 が Mac と違う値になる
（蒲郡市で実際に違った。CRLF に直すと一致した）。`lineterminator="\n"` を付ける。このレシピの fetch.py は `\n` で書く。

## 効くケース
- 市区町村の中の地域差を町丁単位で塗る（産業別就業者の割合、高齢化率、世帯の型 など）。
- 教科書の「〇〇市の中心部と郊外」の説明を、町丁の値で当てる。

## 効かない／別レシピ
| 要求 | 対応 |
|---|---|
| 市区町村単位の値 | `estat/census_age_sex_municipality`（API）か社会・人口統計体系 |
| 年齢5歳階級×男女の人口ピラミッド（市区町村） | `estat/census_age_sex_municipality` |
| 町丁の人口だけを境界つきで | 境界の Shapefile 自体に人口・世帯数の列がある（`--boundary` だけでよい） |
| 2015年以前 | 平成27年にも小地域集計と境界がある（`--year 2015`・`--survey A002005212015`）。**このレシピでは未検証** |

## 参照実装
`gamagori_industry_p000`（蒲郡市・第11表・3部門を3面に並べた階級区分図）。講師の機械で AI が作り、こちらで再現・検算した。
★このプロジェクトの `fetch_estat.py` は列を位置で読み、親への合算（5）を扱わない。**蒲郡市では正しいが、ほかの市に流用するときはこのレシピの fetch.py を使う。**

## このレシピを使う LLM へのヒント
- まず `--find` で番号、`--list-cols` で列を確かめてから `--cols` を決める。見出しを推測で書かない。
- 検算が NG なら、地図に進まない。どの地域で合わないかを、レベル3と秘匿先の列で追う。
- 割合の分母は表の「総数」を使う（分類不能を含む）。分子との差は図の注に書く。
